# Tracker surface direction

## Mode
Operate. Visitors review date-scoped trading results, compare scheduled strategies, adjust lot multipliers, and contact the team.

## Direction
Build an exchange close report with a precise, contemporary editorial voice: cool mineral paper, deep ink navigation, clear teal gains, restrained vermilion losses, and a small amber date signal. Use a condensed display face for titles and a legible monospace for financial values. Keep familiar web navigation, filters, selects, charts, and tables. The page stays a working performance report, never a market-terminal costume.

## First viewport
A fixed strategy rail on wide screens; on compact screens, an accessible menu. The main column starts with the DECAY HUNTERS report name, date-range control, EOD status, and contact action, then moves directly to the daily breakdown. Show strategy and weekday context before capital, lot, daily P&L, and monthly P&L. Wide screens use a fully aligned table; narrow screens use readable stacked rows.

## Visitor path
Select a strategy or all strategies from the rail. Choose date and weekday scope in the report. Change a strategy's lot where its capital and P&L appear. Read the daily report first, then cumulative performance, recent results, drawdown, average P&L by weekday, daily history, statistics, and monthly summary.

## Signature move
A weekday schedule rail sits directly under each strategy name. The date's weekday is highlighted consistently in the rail and in the global weekday filter, so visitors can see at a glance why a strategy is in scope.

## Cross-surface reach
Keep this visual system scoped to the public tracker. Preserve DECAY HUNTERS name and logo, API data and loading/error/empty states, date and weekday filtering across every metric, lot scaling across all P&L and capital figures, descending daily-profit order, and the existing contact destination.

## Quality and risk
Make hierarchy, numeric alignment, contrast, focus, responsive behavior, and reduced-motion support do the work. Keep the existing report language and do not introduce performance claims. The report can feel too much like a document if the editorial type overwhelms the operating screen; keep controls and data structure unmistakably web-native.
